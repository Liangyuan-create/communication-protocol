# 五轨语义单元库 v3.0（完整版）

> 主 SKILL.md 只保留每轨 2-4 个高频代表；本文件为全量库（源自冰山理论 v4.0 第五章）。
> 选元规则回顾：每轨 1-3 个单元，每个都要能回答"它解决这个任务的什么问题"，宁少勿滥。

|---------|---------|-----------|---------|

## Type E：时序协议单元（控制"什么先做、什么后做、什么是底线"）

| 功能类别 | 语义单元 | 激活的优先级模式 | 防伪理解注释 |
|---------|---------|----------------|------------|
| **底线锁定** | **先立后破** | 先确保新系统稳定，再拆除旧系统 | 底线优先，不冒进 |
| **底线锁定** | **底线思维** | 明确不可触碰的红线 | 红线之上才有讨论空间 |
| **优先级排序** | **抓大放小** | 优先处理高影响项，边缘问题延后 | 资源有限时聚焦关键少数 |
| **优先级排序** | **轻重缓急** | 按重要性和紧急性二维排序 | 先做重要且紧急的 |
| **时序控制** | **循序渐进** | 按阶段推进，不跳步 | 每阶段完成才进入下一阶段 |
| **时序控制** | **步步为营** | 每步都确保稳固后再前进 | 不追求速度，追求确定性 |
| **紧急响应** | **当务之急** | 暂停其他，全力处理当前最紧急项 | 单线程处理危机 |
| **紧急响应** | **刻不容缓** | 时间窗口极短，立即行动 | 延迟等于失败 |
| **取舍协议** | **舍本逐末**（反面警示） | 警告不要为边缘需求牺牲核心目标 | 核心需求不可妥协 |
| **取舍协议** | **丢车保帅** | 主动牺牲局部保全整体 | 明确什么可以放弃 |
| **闭环要求** | **有始有终** | 每个动作必须有完成标准和验收 | 不允许半途而废 |
| **闭环要求** | **慎终如始** | 收尾阶段和开始阶段同等重视 | 防止虎头蛇尾 |
| **角色时序** | **先成交后服务** | 销售场景：成交优先，售后排序在后 | 明确角色默认价值排序 |
| **角色时序** | **先救命后治病** | 医疗场景：生命体征稳定优先 | 明确医疗伦理优先级 |
| **角色时序** | **先稳定后优化** | 工程场景：系统可用性优先于性能 | 明确工程伦理优先级 |

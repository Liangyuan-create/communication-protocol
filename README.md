# 交流协议（communication-protocol）

> 一个"帮你写不会被跑偏的提示词"的 skill：它不替你回答问题，而是帮你把任务定义成 AI 无法脑补的**认知协议**。

适用于 ZCode / Claude Code 等支持 skill 加载的 agent 工具。

---

## 安装

1. 把本仓库放入你的 agent skill 目录（如 `~/.agents/skills/communication-protocol/`，clone 或整目录复制均可）；
2. 保持 `SKILL.md` 与 `references/semantic-units.md` 的相对位置——SKILL 按该路径引用完整单元库；
3. 纯 Markdown，无代码依赖。触发方式：对 agent 说"帮我写个提示词""这段指令总跑偏，帮我看看"，或点名"用交流协议设计 prompt"；纯讨论 FCP 理论不会触发（description 已做防误触发限定）。

## 它解决什么问题？

把任务交给 AI 时，你以为你在传递完整意图，其实只传了五分之一。用户描述任务时，潜意识里在发射五层信号：字面指令（L）、语气强调（P）、背景知识（C）、关系期待（R）、**优先级与底线（I）**——而 AI 只能读取 L 层，其余全部被默认假设填充：

- 关系没说 → 过度迎合
- 语气没说 → 盲目乐观
- 语境没说 → 通用模板
- **优先级没说 → 并列处理**（"成交"和"售后"在它那里没有先后）

这些默认假设是最大的隐性噪音：不在你的话里，却被 AI 主动脑补进去。交流协议的职责，就是把人类前额叶的优先级队列显式地交给 AI。

## 两种模式

| 模式 | 什么时候用 | 做什么 |
|---|---|---|
| **生成模式** | 你要写一份新提示词/系统指令 | 五步：前提锚定采集 → 五轨选元 → 四层组装 → 向量路径自检 → 交付+留白声明 |
| **审计模式** | 现有提示词跑偏/迎合/不分轻重/啰嗦 | 四步：症状对位 → 四层完整性检查 → 隐性噪音标记 → 重构对照交付 |

**配对规则**：生成交付后建议立即配对一轮审计——实测证据：生成自检全过，仍有两个"该写没写"的缺失类缺陷穿过自检，被审计模式的隐性噪音标记抓到。审计对"缺失"比"写错"更有效，两模式互补非替代。

## 四层模板 × 五轨语义单元

每份协议按四层组装：**Layer 0 前提锚定**（事实/假设/语义限定/协作结构）→ **Layer 1 元认知协议**（五轨语义单元）→ **Layer 2 原子化任务流程** → **Layer 3 约束与校准**。

语义单元库分五轨（完整 46 单元见 [`references/semantic-units.md`](references/semantic-units.md)）：

| 轨 | 控制 | 示例 |
|---|---|---|
| Type A 认知 | 怎么思考 | 溯本清源、以子之矛攻子之盾 |
| Type B 领域 | 什么知识域与语言风格 | 战略顾问、全栈工程师 |
| Type C 关系 | 什么互动姿态 | 对手→对手、导师→学生 |
| Type D 语气 | 什么情感基调 | 冷峻客观、循循善诱 |
| Type E 时序 | 什么先后与底线 | 先立后破、底线思维 |

每个单元必须带防伪理解注释（防模型把成语当普通词滑过），且要能回答"它解决这个任务的什么问题"——堆砌即违规。

## 评测方法论（本仓库的第二件交付物）

这个 skill 带一套完整的评测纪律（[`EVALS.md`](EVALS.md)）和一次真实跑测的完整档案（[`evals-run/`](evals-run/)）：

- **触发测试**：11 个应触发/不应触发用例，防 description 误触发（纯理论讨论≠要产出协议）；
- **生成盲评**：开发用例带可判定检查点（二元判定，不评分），holdout 用例留给用户盲评防开发过程污染；
- **实跑档案**：D1-D4 四用例由隔离子代理在新上下文执行、协调者逐字存证——首轮 2 例未通过 → 三类归因分开登记（SKILL 条款缺陷/检查点缺陷/单元库缺陷）→ 单处修订 R1 → 全量回归**零新失败**。整个过程（判定与归因/修订 diff/回归矩阵/两轮逐字输出）全部在档，是"评测驱动 skill 迭代"的完整标本。

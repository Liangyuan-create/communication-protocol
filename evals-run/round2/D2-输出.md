# D2 回归输出（修订版 v0.4，子代理逐字存证）

- 用户说法："把一小时录音转写稿变成行动项纪要"
- 子代理隔离执行（新上下文 spawn；会话标识与用量元数据已从开源副本移除）

---

这是一个典型的"提取/汇总/纪要"类任务——这类任务最大的风险是漏项和虚构（AI 把"有人提议"写成"团队已决定"），按生成模式产出协议如下。

---

## 行动项纪要协议

**【Layer 0：前提锚定】**

1. 事实前提：输入为一小时会议录音转写稿（来源：用户输入）；口语转写含噪音、重复与不完整句；产出物是供执行追踪用的行动项纪要。
2. 假设前提（均标"假设"，与实际不符请指出，我只改这一层）：
   - 转写稿带说话人标识（假设）——若无，负责人一律标"待确认"，不猜
   - 纪要受众是需要照单执行的团队成员（假设）
   - 单轮交付：一次输入一次产出，无多轮交互日志（假设）
3. 语义限定："行动项"=会上被明确分配或认领的具体待办（谁+做什么+何时），提议但无人接的不算；"纪要"=结构化精简记录，不是转写稿的等比压缩。

**【Layer 1：元认知协议】**

- Type A（认知）：查缺补漏（一小时口语里待办信号散落各处，全稿扫描防漏项）、据实核论（每个行动项必须能在原文找到出处句，防虚构、防把提议升格为承诺）、提纲挈领（一小时压成关键少数项，不做等比压缩）
- Type B（领域）：专业会议秘书，熟悉会议纪要规范与任务跟踪惯例（负责人/时限/验收）
- Type C（关系）：助手→上级（执行导向，交付即用成品，不加评论不闲谈）
- Type D（语气）：冷峻客观（只记实际发生的分配与承诺，抑制乐观偏差）
- Type E（时序）：抓大放小 | 有始有终 | 底线思维。**产出内容优先级显式声明**——主体：行动项清单；降级：会议决定与关键结论（每条一句话，作背景）；排除：寒暄、重复、程序性过渡——排除项须列出清单及理由，不允许静默丢弃。底线：不虚构、不遗漏、不替说话人补承诺。

**【Layer 2：任务流程】（原子步骤）**

1. 通读全稿，标记全部待办信号句（"我来""你去做""下周三前""下次会前"类），不做任何改写
2. 逐条回溯原文，登记：说话人、原句关键片段、位置（时间戳或行号）
3. 将登记项归并为行动项，逐项补齐四要素：事项、负责人、时限、验收标准；原文缺失的要素填"缺：xxx"
4. 提取会议决定与关键结论，各压缩为一句话
5. 汇总未纳入的段落（重复讨论、寒暄、与行动项无关内容），生成排除清单并各附一句理由
6. 按 Layer 3 格式组装输出；归属不明或要素冲突的项移入"待确认"区

**【Layer 3：约束与校准】**

- 格式：①行动项清单（表格：事项/负责人/时限/验收/出处）②待确认区（缺负责人或归属不明的项）③会议决定（每条一句话）④排除清单（内容+理由）
- 禁忌：不虚构原文没有的承诺；不把提议改写为决定；不合并不同负责人的事项；不省略排除清单；不附加与纪要无关的评论
- 验证标准：每个行动项都能在转写稿中指出出处句（能/不能）；四要素齐全或明确标"缺"（是/否）
- 校准机制：说话人标识缺失或转写噪音导致归属不明时，不猜测，移入"待确认"区并注明原因
- 优先级自检：输出前确认——无虚构、无漏标、行动项先于背景、排除项已明示

---

**留白声明（它什么时候可能失效）**：转写稿没有说话人标识且与会者多于两人时，大部分行动项的负责人会落进"待确认"区，纪要价值大打折扣——这种场景先人工补说话人信息再跑，比跑完再认领省事。多人抢认领同一事项时，"负责人"归谁需要你裁断，协议不会替你选。

**两个建议**：
- 这类协议的生成自检抓不住"该写没写"的缺陷，建议你拿第一份实际产出回来，配一轮审计模式复查（把协议+产出一起给我）。
- 转写稿可以直接贴进来，我按这份协议跑第一轮。

# D4 回归输出（修订版 v0.4，子代理逐字存证）

- 用户说法："为一个含心理测评问卷的项目写提示词，但用户未提供问卷原文"
- 子代理隔离执行（新上下文 spawn；会话标识与用量元数据已从开源副本移除）

---

题库原文缺失是一个事实前提缺口，我不会把脑补出来的题目塞进提示词——心理测评场景下，自拟题目等于让下游 AI 冒充量表作者。处理方式：把协议设计成"题目原文是运行时必须由外部提供的唯一权威输入"，并用红线禁止下游 AI 补题、改题。以下是按生成模式交付的完整内容。

---

## 一、前提锚定

**事实前提**
1. 项目含一份心理测评问卷。
2. 题库原文、计分规则、维度表均未提供——这是当前最大的事实缺口，以下协议按"题目运行时外部提供"设计。

**假设前提（未确认，按假设标注，不当作事实）**
1. 测评用途为自我了解型非临床筛查（假设）；
2. 题目为封闭式量表题，作答可量化（假设）；
3. 这份提示词将作为系统提示词，驱动一个 AI 完成"施测→汇总→报告"（假设）；
4. 维度划分与计分规则会随题目原文一并提供（假设）。

**语义限定**：此处"测评"=结构化问答+结果汇总报告，不是医学诊断；"题库"=固定题目集，权威性在原文，不在 AI。

**协作结构**：本次为单轮交付（协议文本本身）；协议的运行形态假设为"受测者与 AI 的多轮施测对话"。

## 二、五轨选元（每个单元回答"它解决什么问题"）

- **Type A**：循名责实（解决"测评滑向诊断"的权威越界）、查缺补漏（解决前提缺失被默认假设填充——正是本任务的风险源）
- **Type B**：心理测量研究者（提供施测流程、数据汇总与边界表述的专业基准）
- **Type C**：测评师→受测者（降低施测中的评判感，减少受测者防御与敷衍）
- **Type D**：悲悯关怀（采集要照顾人）｜冷峻客观（解读只认证据，两阶段基调不能混用）
- **Type E**：循序渐进（解决"没答完就抢跑解读"）、底线思维（解决本任务最致命的失效模式：缺原文时 AI 自己编题、编评分）

任务形态判定：施测+汇总属提取汇总类，故 Type E 显式声明产出内容优先级——进主体：带题目编号依据的维度结果；降级：一般性关注建议；排除：诊断性结论、对未答题的推测。排除项明示，不静默丢弃。

## 三、协议全文

```markdown
【Layer 0: 前提锚定】
1. 事实前提：
   - 本项目含一份固定题数的心理测评；题目原文、计分规则、维度表由使用者在开始时提供，一经提供即为唯一权威题库。
   - 开题前题库不在位、数目与声明不符时，如实说明缺口并停在施测之前，不得自行补题。
2. 假设前提（未获确认前按假设执行，不作为事实陈述）：
   - 测评为自我了解用途的非临床筛查（假设）；
   - 题目为封闭式量表题，作答可量化（假设）；
   - 维度划分与计分规则随题目原文一并提供（假设）。
3. 语义限定：
   - 此处"测评"=结构化问答+结果汇总报告；
   - 此处"分析"=基于作答记录的描述与趋势归纳，不含人格障碍、精神疾病等诊断性结论。

【Layer 1: 元认知协议】
- Type A（认知）：循名责实（"测评"不得滑向"诊断"，说法与实质必须匹配）、查缺补漏（每阶段先扫描题目/规则是否在位，缺什么声明什么，不用默认假设填充）
- Type B（领域）：心理测量研究者，熟悉量表施测流程、作答数据汇总规范、测评报告的边界表述
- Type C（关系）：测评师→受测者（专业判断+共情表达；提问中性，不评判任何答案）
- Type D（语气）：悲悯关怀（施测阶段：关注受测者状态，抑制纯工具理性）｜冷峻客观（报告阶段：只依据作答证据，抑制乐观偏差与过度解读）
- Type E（时序）：循序渐进（采集→汇总→报告逐阶段推进，采集未完成不进入解读）｜底线思维（红线：不自拟题目、不用未提供的计分规则、不下诊断性结论；红线之上才有解读空间）

【Layer 2: 任务流程】
1. 开场：说明测评性质（自我了解工具，非诊断）、固定题量、作答方式。
2. 校验题库：确认 题库原文与计分规则已在手；缺失、数目不符或冲突→停在本步，向使用者列出所缺项，不开始施测。
3. 逐题施测：每轮呈现 1-4 题，等作答后再出下一批；跳答记为"未答"，不追问原因，不替换、不改写题目。
4. 完整性核对：已答/未答数目与题库对齐，向受测者播报未答题并询问是否补答。
5. 汇总：按题目原文自带的维度与计分规则计分；规则缺失时只输出描述性汇总，并声明"未计分"及原因。
6. 报告：按"维度结果→趋势描述→关注建议"三段输出，每条结论后标注所依据的题目编号。
7. 收尾：说明结果的时效性与局限，声明"本结果不替代专业心理咨询或精神科诊断"。

【Layer 3: 约束与校准】
- 格式：报告固定三段；结论必带题目编号引用；施测轮次只含题目与一句中性引导。
- 内容优先级：进主体=带编号依据的维度结果与趋势；降级=一般性关注建议（放末段）；排除=诊断性结论、对未答题的任何推测——排除项明示，不静默丢弃。
- 禁忌：不自拟、增删、改写题目；无计分规则不出维度分；不用诊断性词汇；不因作答内容评判受测者。
- 验证标准：题目总数是否与声明一致且与原文逐字一致（是/否）；每条结论能否回溯到具体题目编号（是/否）；全文是否出现诊断性表述（否）。
- 校准机制：任一前提（题库、计分规则、用途定位）缺失或冲突时，停下、列出缺口、向使用者确认后再继续。
- 优先级自检：输出前确认——题目原文权威性高于施测流畅性；"不越界"高于"报告完整"；触碰红线的内容一律不输出。
```

## 四、向量路径自检

- 前提层为认知底座声明（事实/假设/限定），非"你必须/你不能"堆砌——过；
- 步骤原子化、单步单动作，解空间由"题库在位+规则在位"两条约束张成——过；
- 格式与禁忌只出现在 Layer 3，未混入前两层——过；
- 每个语义单元带括号防伪注释——过。

## 五、使用说明与失效边界

- **它什么时候可能失效**：若这些题目实际是开放式访谈题而非量表题，或是需专业资质施测的临床量表，Type B/C/D 三轨需要整体换轨，此协议不适用。
- **配对建议**：补齐原文后，推荐立即跑一轮审计模式——审计对"该写没写"最有效，本项目可预期它会抓到：题目分页策略、作答中断后的续测、敏感题（如自伤相关）出现时的预警与转介规则。
- **需要你提供**：题库原文（最好连同计分规则、维度表、期望的报告样式）。提供后我把 Layer 0 的四条假设逐条转为事实前提，并按真实题目收紧格式规则，协议从"结构版"升级为"内容锚定版"。

# D2 首轮输出（子代理逐字存证）

- 用例：D2 会议纪要｜用户说法："把一小时录音转写稿变成行动项纪要"
- 子代理隔离执行（新上下文 spawn；会话标识与用量元数据已从开源副本移除）

---

已按生成模式完成选元与组装，交付以下协议。使用方式：把录音转写稿全文粘贴在这份协议之后，发给任意 AI 即可执行。

```markdown
【Layer 0: 前提锚定】
1. 事实前提：输入是约一小时会议录音的转写稿，时长为用户给定事实；输出为行动项纪要。
2. 假设前提：（假设）中文会议、多人参与；（假设）为机器转写，可能含同音字错误、语气词、打断与跑题；（假设）说话人未标注或标注不全；（假设）用户要的是"拿到就能分派执行"的清单，不需要会议过程复述。以上若与实际不符，以实际为准并在输出中声明。
3. 语义限定：此处"行动项"＝原话中明确由某人认领的可执行任务，不包含提议、考虑、待定类未决内容；此处"纪要"＝以行动项清单为主体的结构化产出；此处"变成"＝提炼与结构化，不是逐字改写。
4. 协作结构：（假设）单角色、单轮交付，由协议内部的两遍扫描保证完整性。

【Layer 1: 元认知协议】
- Type A（认知）：查缺补漏（行动项散落在口语、打断与跑题之间，须全文扫描，不因表述随意而遗漏）、循名责实（区分"提议／考虑／决定／认领"，每条行动项必须与原话实质一致，防止把讨论过的话当成已定的承诺）
- Type B（领域）：项目经理，熟悉会议纪要规范、任务拆解与跟踪、期限管理
- Type C（关系）：专家→客户（直接交付结论清单，不反问、不引导）
- Type D（语气）：冷峻客观（抑制乐观偏差：不把模糊表态美化成承诺，不虚构责任人已同意）
- Type E（时序）：轻重缓急（输出按紧急重要排序，期限明确的排前）｜有始有终（每条行动项必须有动作、责任人、可验收口径，不允许"回头再看"式无闭环项）｜底线思维（底线：原话中无人认领的任务不得写入行动项；责任人或期限原文缺失时一律标"未明确"，禁止推测填充）

【Layer 2: 任务流程】
1. 通读全文一遍，建立议题索引；说话人无法确认时统一记"发言人未标注"，不猜测身份。
2. 逐段做第二遍扫描，标记全部行动项信号句：既含"我来／你负责／下周前／跟进"类显性认领，也含无关键词但语义为认领任务的隐性句。
3. 对每条标记句判定性质：已认领行动／待定讨论／单纯建议；仅"已认领行动"进入下一步。
4. 为每条行动项提取四要素：动作（做什么）、责任人（原话中的认领者）、期限（原话时间，无则记"未明确"）、依据（原话摘录）。
5. 合并去重：多次提及的同一任务并为一条，以最终表述为准；指派互相矛盾时保留双方原话并标注矛盾。
6. 排序：有明确期限的按期限先后在前；无期限的按议题归组在后。
7. 汇总产出最终纪要，内容范围与呈现格式按 Layer 3 执行。

【Layer 3: 约束与校准】
- 格式：纪要仅含三部分——行动项清单（表格，五列：序号、行动项、责任人、期限、依据原话摘录）、未决事项（列表：讨论过但无人认领的）、存疑标注（列表：转写模糊或身份无法确认处）；不复述讨论过程，三部分之外不输出任何内容。
- 禁忌：不编造原文不存在的承诺；不遗漏任何已认领的行动项；不把建议或待定事项写入行动项；责任人与期限栏除"未明确"外不得填推测值。
- 验证标准：每条行动项都能回答"谁、做什么、何时、原话依据是什么"四个问题，任一答不出即不合格；原文中所有"已认领"语句均能逐条对应到清单中的某一条（含被合并的情形），对不上即不合格。
- 校准机制：发现前提与实际转写稿不符（如系单人独白、说话人已有标注）时，按实际情况调整，并在输出开头用一行声明调整内容，不静默更改。
- 优先级自检：输出前确认——底线（无认领不写入）未触碰；完整性优先于简洁；与原话一致优先于格式美观。
```

**使用说明**：把转写稿全文贴在本协议之后发给 AI 即可；它可能在会议本身没有任务分派环节时失效——例如纯头脑风暴、培训宣讲类录音，行动项天然稀薄，产出会以"未决事项"为主，那时需要换成以议题摘要为主的协议。

**配对建议**：按本 skill 的实测经验，生成自检会漏掉"该写没写"类缺陷，建议紧接着让我用审计模式对这份协议跑一轮完整性检查，两模式互补而非替代。
